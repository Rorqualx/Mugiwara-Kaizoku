# Multi-source data fusion and entity resolution methods for a small manga metadata pipeline

Reading notes on verification level. Sources marked **[full text]** were read in full or in the relevant sections this session. Sources marked **[abstract]** were confirmed only at abstract / search-snippet level; their details should be re-checked before being quoted as findings. Anything under "Inferences" is this researcher's reasoning, not something the cited literature states.

The four recurring failures referred to throughout:
- **F1** — a confident, internally consistent source that describes a different edition or work.
- **F2** — one bad scalar poisoning a derived limit.
- **F3** — invented values written as if sourced.
- **F4** — results flipping between runs when a provider's answer changes.

## 1. Truth discovery / data fusion: what the standard methods assume, and which work with 3–8 sources and numeric/range claims

### Takeaway
The literature's own benchmarks say no truth-discovery algorithm consistently wins, that unsupervised reliability estimation is the weak link, and that knowing source accuracy from a labelled sample fixes about half of the remaining errors. For 6–8 sources the supportable recommendation is weighted voting with per-source-per-field accuracies measured on a gold set, an explicit "unknown" output, and tolerance-bucketed numeric comparison; iterative methods (TruthFinder, Accu, CRH, Dawid–Skene) add little at this scale and add instability. The biggest single cause of conflict in the benchmark data was not error but semantic ambiguity (sources meaning different things by the same attribute), which no voting scheme resolves.

### Cited Findings

**Baseline taxonomy of conflict handling (Bleiholder & Naumann, via Dong & Naumann tutorial)**
- Strategies are classed as conflict *ignoring* (unaware of conflicts, may produce inconsistent results), *avoiding* (one decision such as a source preference applied to all conflicts), and *resolving* (an individual decision per conflict). Resolution is *instance-based* (looks at the values) or *metadata-based* (freshness, source reliability), and *deciding* (picks an existing value) or *mediating* (may produce "an entirely new value", such as an average). **[full text]** — [Dong & Naumann, "Data Fusion – Resolving Data Conflicts for Integration", VLDB 2009 tutorial](https://lunadong.com/publication/fusion_vldbTutorial.pdf)
- Named strategies in the tutorial's Table 2: "Pass it on" (escalate to user/application), "Consider all possibilities", "Take the information" (prefer values over nulls), "No Gossiping" (return only consistent tuples), "Trust your friends" (take a preferred source's value), "Cry with the wolves" (most frequent value), "Roll the dice" (random), "Meet in the middle" (average), "Keep up to date" (most recent). **[full text]** — [Dong & Naumann tutorial](https://lunadong.com/publication/fusion_vldbTutorial.pdf)
- The tutorial states none of these simple strategies is adequate, for three reasons: accurate sources also make mistakes; the true value changes over time so "taking the most common value may end up with an out-of-date value, whereas taking the most recent value may end up with a wrong value"; and sources copy from each other so errors propagate. It names a third value state besides true/false: *out-of-date*. **[full text]** — [Dong & Naumann tutorial](https://lunadong.com/publication/fusion_vldbTutorial.pdf)

**General principle and method families (Li et al. survey)**
- The shared principle: sources that provide true information more often get higher reliability, and information supported by reliable sources is regarded as truth. Reliability is "usually unknown a priori" and inferred from the data, so truth computation and weight estimation are iterated to convergence. **[full text]** — [Li et al., "A Survey on Truth Discovery", 2015](https://arxiv.org/abs/1505.02463)
- Three formulations: *iterative* (TruthFinder, Investment, 2-/3-Estimates), *optimization-based* (CRH: minimise the sum over objects and sources of weight × distance between claim and truth, with 0–1 loss for categorical and L2 for continuous), and *probabilistic graphical models* (GTM, LTM, LCA; inferred with EM). The survey says these lead to similar update rules and does "not claim that one of them is better than another". **[full text]** — [Li et al. survey, §2.2](https://arxiv.org/abs/1505.02463)
- Majority voting's stated shortcoming is that it assumes all sources are equally reliable; truth discovery can break ties and can output a minority value ("the wisdom of minority"). **[full text]** — [Li et al. survey, §1–2.2](https://arxiv.org/abs/1505.02463)

**Assumptions the methods make (each is a way the manga setting can break them)**
- *Source consistency*: a source provides true information with the same probability for all objects. The survey calls this one of the most important assumptions, and notes it stops holding as observations grow, in which case per-attribute or per-object-cluster reliabilities are better (a website can be treated "as multiple sources according to attributes"). **[full text]** — [Li et al. survey, §3.2.1, §3.2.4](https://arxiv.org/abs/1505.02463)
- *Source independence*: sources observe independently; equivalently, true values tend to coincide across sources while false values differ. Copy detection (Accu/AccuCopy line) relaxes this using the principle that sources sharing many common mistakes are unlikely to be independent; the survey notes this "becomes ineffective when some sources copy information from a good source". **[full text]** — [Li et al. survey, §3.2.2–3.2.3](https://arxiv.org/abs/1505.02463)
- *Single truth*: one and only one true value per object, with a claim for one value treated as a vote against the others (complementary vote). LTM relaxes this for multi-valued attributes by modelling precision and recall separately. **[full text]** — [Li et al. survey, §3.4.1, §3.5.1](https://arxiv.org/abs/1505.02463)
- *Object independence*: most methods assume objects are unrelated, although related facts (the survey's example is birth year vs age) could improve results; Investment/PooledInvestment can take such relations as propositional constraints. **[full text]** — [Li et al. survey, §3.3.2](https://arxiv.org/abs/1505.02463)
- *One observation per source per object*, and *uniform weight initialisation*: with uniform initialisation "the behavior of truth discovery is identical to voting/averaging" at the start, ties are broken arbitrarily, and results "rely on the majority to a certain extent". **[full text]** — [Li et al. survey, §3.1.1, §3.2.6, §5](https://arxiv.org/abs/1505.02463)
- An independent re-implementation of 12 algorithms lists the same assumptions (uniform contribution of a source across its claims; all claims positive; exactly one true claim per item except LTM; sources, claims and objects independent except in the Depen family). **[full text]** — [Waguih & Berti-Equille, "Truth Discovery Algorithms: An Experimental Evaluation", 2014](https://arxiv.org/abs/1409.6428)

**Per-method notes relevant to numeric/range claims**
- TruthFinder: Bayesian iterative estimation; introduced the source-consistency assumption and "implication" between values (175 cm supports 176 cm more than 185 cm). TruthFinder, AccuSim and AccuCopy focus on categorical data but extend to continuous data through an implication (similarity) function. **[full text]** — [Li et al. survey, §3.4.2–3.4.3, §4](https://arxiv.org/abs/1505.02463)
- AccuSim / AccuCopy: Bayesian; AccuCopy "reduces the weight of a source if it is detected as a copier". The original paper's heuristic is that sharing many values, especially rare/false ones, indicates copying. **[full text for survey; abstract for original]** — [Li et al. survey, §4](https://arxiv.org/abs/1505.02463); [Dong, Berti-Equille & Srivastava, VLDB 2009](https://lunadong.com/publication/dependence_vldb.pdf)
- 3-Estimates adds per-object difficulty, so an error is charged partly to the object and partly to the source. **[full text]** — [Li et al. survey, §3.3.1](https://arxiv.org/abs/1505.02463)
- GTM, CRH and CATD are designed for continuous data; CRH is the framework for heterogeneous data where a distance function per data type is plugged in and reliability is estimated jointly across types. **[full text]** — [Li et al. survey, §4](https://arxiv.org/abs/1505.02463)
- CATD targets sources with very few claims: a point estimate of reliability is not reasonable, so it uses a confidence interval and discounts small sources. **[full text for survey; abstract for original]** — [Li et al. survey, §3.2.5, §4](https://arxiv.org/abs/1505.02463); [Li et al., "A Confidence-Aware Approach for Truth Discovery on Long-Tail Data", PVLDB 8(4)](https://cse.buffalo.edu/~jing/doc/vldb15_CATD.pdf)
- Dawid–Skene (1979) models each worker/source as a confusion matrix and fits by EM; in a 17-method benchmark it and its extensions (BCC, LFC) were generally the most robust for single-label tasks. **[full text]** — [Zheng et al., "Truth Inference in Crowdsourcing: Is the Problem Solved?", PVLDB 10(5), 2017](https://www.vldb.org/pvldb/vol10/p541-zheng.pdf)
- Knowledge-Based Trust scores a source by the correctness of the facts it states, using a multi-layer model to separate extraction errors from source errors; it was applied to 2.8 billion extracted facts to score 119 million web pages. **[abstract]** — [Dong et al., "Knowledge-Based Trust", 2015](https://arxiv.org/abs/1502.03519)

**"Unknown" as an output and labelled truths as an input**
- Investment-style methods add an extra candidate "unknown" per object, so constraints can always be satisfied and objects with no truth can correctly return unknown; other methods can be modified the same way by adding one more candidate value. **[full text]** — [Li et al. survey, §3.5.2, §4](https://arxiv.org/abs/1505.02463)
- Truths returned by GTM and similar mediating methods "are not necessarily be observed or claimed by any sources". **[full text]** — [Li et al. survey, §3.5.3](https://arxiv.org/abs/1505.02463)
- Semi-supervised use: "even a small set of labeled truths could improve the performance"; in practice most methods can be modified by replacing aggregated results with labelled truths each iteration. **[full text]** — [Li et al. survey, §3.1.7, §4](https://arxiv.org/abs/1505.02463)
- SLiMFast frames fusion as a discriminative model (often logistic regression); with ground truth it uses ERM instead of EM, and reports good source-accuracy estimates from very few labels (the abstract cites as few as 50 training examples). **[abstract]** — [Joglekar et al., "SLiMFast", SIGMOD 2017](https://arxiv.org/abs/1512.06474)

**What the benchmarks found**
- Deep-web study, 55 stock sources and 38 flight sources: for 70% of data items more than one value was provided. Of the inconsistency, "nearly 50% are caused by various kinds of ambiguity", 20% by out-of-date data and 30% by pure mistakes. Only 70% of correct values were provided by a majority of sources. **[full text]** — [Li, Dong, Lyons, Meng & Srivastava, "Truth Finding on the Deep Web: Is the Problem Solved?", VLDB 2013](https://arxiv.org/abs/1503.00303)
- In the Stock domain 46% of inconsistency was semantic ambiguity (a source applying different semantics to an attribute) and a further 6% instance ambiguity (a source interpreting one identifier as a different entity); in Flight, semantic ambiguity was 33% (e.g. takeoff time vs gate-departure time). Bloomberg scored only .83 accuracy because it "may apply different semantics" on some attributes. **[full text]** — [Li et al., Deep Web, §3](https://arxiv.org/abs/1503.00303)
- Voting works when dominance is high and fails otherwise: where the dominant value had over half the sources (73% of Stock items) it was right 98% of the time, but at a dominance factor of .1 the precision of the first/second/third most common value was .43/.33/.12. **[full text]** — [Li et al., Deep Web, §3.2](https://arxiv.org/abs/1503.00303)
- Copying among low-accuracy sources depressed voting precision in Flight; removing copiers raised it. Where copying is among low-accuracy sources, "considering source accuracy without copying can obtain results with even lower precision". **[full text]** — [Li et al., Deep Web, §3.4, §4](https://arxiv.org/abs/1503.00303)
- Best fusion methods were right on about 96% of items on average, but "we did not find one method that is consistently better than others", and an "improved" method did not reliably beat its base method. **[full text]** — [Li et al., Deep Web, §1, §4](https://arxiv.org/abs/1503.00303)
- "It is essential that accurate information on source trustworthiness and copying between sources is used; otherwise, fusion accuracy can even be harmed." All methods beat VOTE on Flight once sampled (gold-standard) trustworthiness was supplied, "showing that the problem lies in trustworthiness computation"; about 50% of the best method's remaining mistakes "can be fixed by correct knowledge of source trustworthiness and copying". **[full text]** — [Li et al., Deep Web, §4](https://arxiv.org/abs/1503.00303)
- More sources is not better: fusing a few high-recall sources (5 for Stock, 9 for Flight) gave the highest recall, "while adding more sources afterwards can only hurt". The survey reports the same from other work: incorporating bad sources "may even hurt". **[full text]** — [Li et al., Deep Web, §4](https://arxiv.org/abs/1503.00303); [Li et al. survey, §3.2.7](https://arxiv.org/abs/1505.02463)
- Per-attribute trustworthiness (AccuSimAttr / AccuFormatAttr) "in general obtain higher precision than most other methods in both domains". **[full text]** — [Li et al., Deep Web, §4](https://arxiv.org/abs/1503.00303)
- Numeric values were compared with a tolerance: values are bucketed around the dominant value with a tolerance factor α (default .01) so slightly different numbers count as agreement. **[full text]** — [Li et al., Deep Web, §3.2](https://arxiv.org/abs/1503.00303)
- 12-algorithm evaluation: "none of the methods constantly outperforms the others"; all models need "complex, ad hoc parameter setting", and settings tuned on one dataset did not transfer; LTM and 3-Estimates had repeatability problems; no method did significantly better than random when there were few conflicts per item and many unreliable sources; majority voting "remains the most efficient and scalable for a minor degradation in precision" against methods 9× to 120× slower. **[full text]** — [Waguih & Berti-Equille, conclusions](https://arxiv.org/abs/1409.6428)
- Crowdsourcing benchmark: "no algorithm that outperforms others consistently"; quality "significantly increases with small redundancy, and keeps stable for a large redundancy" (on one dataset stable from 5 answers per task). Its recommendation is majority vote when redundancy is large (over 20), and Dawid–Skene for low overhead with good results. Seeding worker quality from a qualification test did not help every method; with 3 answers per task almost all methods benefited, with 20 answers only two did. **[full text]** — [Zheng et al., PVLDB 2017, §6–7](https://www.vldb.org/pvldb/vol10/p541-zheng.pdf)

### Inferences
- **Scale mismatch.** Every benchmark above uses 38+ sources or hundreds of crowd workers; none tests 3–8 sources. With 6–8 providers and a handful of fields, unsupervised EM has roughly 6–8 × (number of fields) reliability parameters and nothing but the providers' mutual agreement to fit them from — exactly the "relies on the majority" regime the survey warns about. The supervised route (measure each provider's accuracy per field on a gold set, then do fixed-weight voting) is the option the Deep Web results most directly support ("knowing precise trustworthiness can fix nearly half of the mistakes"). This is an inference; no source evaluates the 6–8-source case.
- **Per-field, not per-provider, weights.** The source-consistency assumption is the one the pipeline already violates (a provider good at status and bad at chapter counts). The literature's fix — treat (provider, attribute) as the source — is cheap at this scale and matches the Deep Web finding that per-attribute trust was the most consistently good variant.
- **F1 is not a truth-discovery problem.** The largest single cause of conflict in the Deep Web data was semantic/instance ambiguity, and that paper's own conclusion is that under ambiguity "for each semantics there is a true value so there are multiple truths". A different-edition answer is a correct answer to a different question; weighting cannot fix it, and the single-truth assumption actively mis-penalises the source. It belongs to the entity-resolution step (section 2): claims should be keyed by (edition, field), not (series, field), before any vote.
- **Copying matters more with few sources.** If two of eight manga providers derive from a third (plausible for aggregators that import from one upstream), a "3-of-8 agreement" is one observation. Formal copy detection needs many shared *false* values to detect copying and is not feasible on thousands of entities with confidence; the practical substitute is to declare known derivations by hand and count a derivation group as one vote. Hand-declaring is my suggestion, not a literature method.
- **Deciding vs mediating addresses F3.** A *deciding* rule (the output must be a value some source actually claimed, or "unknown") is a structural guarantee against invented values; any *mediating* rule (average, extrapolated range, gap-filled manifest) produces values no source claimed and should be stored as derived, never as sourced.
- **Numeric claims.** For counts, the literature's two tools are an implication/similarity function (near values support each other) and tolerance bucketing. For volume/chapter counts, exact integer agreement is the natural bucket for completed series and a "≥" semantics for ongoing ones (a stale provider reporting 30 while the truth is 34 is out-of-date, not wrong — the tutorial's third state). Treating stale-low values as lower bounds rather than as competing claims is my inference.
- **Dawid–Skene** fits categorical fields with a small closed value set (publication status: ongoing / completed / hiatus / cancelled) and would capture systematic confusions such as one provider reporting "completed" for hiatus. With a gold set the confusion matrix can simply be counted rather than fitted by EM.

### Gaps
- No source found evaluates truth discovery with fewer than about 18 sources; the "small-source" guidance above is extrapolation from benchmark conclusions.
- The original TruthFinder (Yin, Han & Yu, KDD 2007), CRH (Li et al., SIGMOD 2014) and Dawid–Skene (1979) papers were not retrieved; their descriptions here come from the Li et al. survey and the Zheng et al. benchmark.
- No truth-discovery work on *range-valued* or *partition-valued* claims (such as per-volume chapter ranges) was found; the survey covers categorical, continuous, heterogeneous and hierarchical values only.
- The Bleiholder & Naumann 2008 ACM Computing Surveys article itself was not retrieved; the strategy table is as reproduced in the 2009 tutorial.
- Knowledge Vault / "From Data Fusion to Knowledge Fusion" was not retrieved.

## 2. Entity resolution / record linkage before fusion: same entity vs related entity

### Takeaway
Library science and the three large open catalogues all separate the abstract work from its published editions and attach different facts to each level; volume count, page count, ISBN and publisher are edition-level facts, so fusing them across editions is a category error rather than a conflict. Probabilistic linkage (Fellegi–Sunter) gives an explainable additive score for "is this provider record the same edition", is usable without training infrastructure, and naturally yields a three-way outcome (match / possible / non-match) rather than a forced bind.

### Cited Findings

**FRBR / IFLA LRM**
- FRBR Group 1: a *work* is a "distinct intellectual or artistic creation"; an *expression* is the specific form the work takes each time it is realised; a *manifestation* is "the physical embodiment of an expression"; an *item* is "a single exemplar of a manifestation". **[full text of encyclopedia summary]** — [Wikipedia, Functional Requirements for Bibliographic Records](https://en.wikipedia.org/wiki/Functional_Requirements_for_Bibliographic_Records)
- FRBR's derivative relationships cover editions, versions, translations, summaries and digests on one side, and adaptations "that become new works" on the other. The page notes the hierarchy is "not strictly hierarchical" and that the work/expression boundary is unclear in many cases. **[full text of encyclopedia summary]** — [Wikipedia, FRBR](https://en.wikipedia.org/wiki/Functional_Requirements_for_Bibliographic_Records)
- IFLA LRM (Riva, Le Bœuf & Žumer, August 2017) unifies FRBR, FRAD and FRSAD and keeps the same Work–Expression–Manifestation–Item model. **[full text of encyclopedia summary]** — [Wikipedia, IFLA Library Reference Model](https://en.wikipedia.org/wiki/IFLA_Library_Reference_Model)
- In LRM-based serial modelling, each issue of a serial is an aggregate manifestation and the complete serial has a whole/part relationship to its issues published over time. **[search-snippet level only]** — [RDA Toolkit, "Modeling of serials"](https://rdatoolkit.org/sites/default/files/rsc/Modeling%20of%20serials.pdf)

**Wikidata**
- WikiProject Books collapses FRBR's expression and manifestation into one "edition" layer, leaving two: *work* and *edition* ("version, edition or translation", Q3331189). Works carry title, author, genre, subject, characters, series links; editions carry translator, illustrator, edition number, publisher, place and date of publication, number of pages, ISBN. **[full text]** — [Wikidata:WikiProject Books](https://www.wikidata.org/wiki/Wikidata:WikiProject_Books)
- The two layers are linked by inverse properties: "has edition or translation" (P747) on the work and "edition or translation of" (P629) on the edition. A new edition item is needed if content, pagination, publisher or place changes; an identical reprint does not need one. Translations are edition items. **[full text]** — [Wikidata:WikiProject Books](https://www.wikidata.org/wiki/Wikidata:WikiProject_Books)
- For multi-volume editions, "number of parts of this work" (P2635) takes volume or chapter as its unit, with start/end time for first and last volume; volume (P478) and chapter (P792) are used as qualifiers. **[full text]** — [Wikidata:WikiProject Books](https://www.wikidata.org/wiki/Wikidata:WikiProject_Books)

**MusicBrainz**
- A *release* is "something you can buy"; a *release group* "embraces the overall concept of an album" and groups releases into one logical entity. Every release belongs to exactly one release group. **[full text]** — [MusicBrainz, Release Group](https://musicbrainz.org/doc/Release_Group)
- Same release group: regional variants, deluxe editions, a transliterated release, a version with a bonus disc, a remaster with a bonus track, a vinyl original and a later CD. Track counts therefore legitimately differ between releases of one group. **[full text]** — [MusicBrainz, Release Group](https://musicbrainz.org/doc/Release_Group)

**Open Library**
- Aim: "one work record for every book" with editions under it. Reprints, facsimiles, abridgements, revisions, illustrated editions, translations and annotated editions are editions of the same work. Summaries, dramatizations, novelizations, adaptations, parodies and partial works are *separate works*. Each format (hardcover vs paperback) is a distinct edition. **[full text]** — [Open Library, Editing FAQ](https://openlibrary.org/help/faq/editing)
- A boxed set with its own ISBN is treated as an omnibus edition, with individual volumes also added separately; volumes sold together without a set ISBN are added only individually. Series membership is a tag, not part of the title. **[full text]** — [Open Library, Editing FAQ](https://openlibrary.org/help/faq/editing)
- Fixing an edition attached to the wrong work is a first-class operation ("What work is this an edition of?" / "Move to a new work"), restricted to librarians, as is merging. **[full text]** — [Open Library, Editing FAQ](https://openlibrary.org/help/faq/editing)

**Fellegi–Sunter probabilistic linkage**
- For each comparison field, *m* = Pr(observation | records match), a measure of data quality, and *u* = Pr(observation | records do not match), a measure of coincidence. The Bayes factor is K = m/u; match weight is log2(λ/(1−λ)) + Σ log2(m_i/u_i), where λ is the prior probability that two records match; match probability is 2^M / (1 + 2^M). **[full text]** — [Splink documentation, "The Fellegi-Sunter model"](https://moj-analytical-services.github.io/splink/topic_guides/theory/fellegi_sunter.html)
- The additive form rests on the assumption that observations from different comparisons are independent of one another. **[full text]** — [Splink documentation](https://moj-analytical-services.github.io/splink/topic_guides/theory/fellegi_sunter.html)
- In Splink's workflow *u* is estimated by random sampling of record pairs and *m* by expectation maximisation; Fellegi and Sunter showed these weights minimise one error type for a fixed level of the other; the conditional-independence assumption is known to be violated in practice. **[search-snippet level only]** — [GOV.UK, "Splink: MoJ's open source library for probabilistic record linkage at scale"](https://www.gov.uk/government/publications/joined-up-data-in-government-the-future-of-data-linking-methods/splink-mojs-open-source-library-for-probabilistic-record-linkage-at-scale)

**Collective ER**
- Bhattacharya & Getoor resolve co-occurring references jointly with a relational clustering algorithm using both attribute and relational information, and report improvement over attribute-only pairwise baselines. **[abstract]** — [Bhattacharya & Getoor, "Collective Entity Resolution in Relational Data", TKDD 2007](https://linqs.org/assets/resources/bhattacharya-tkdd07.pdf)

**Entity resolution precedes fusion**
- The tutorial positions data fusion as the step after schema mapping and record linkage: fusion merges records already known to represent the same real-world entity. **[full text]** — [Dong & Naumann tutorial](https://lunadong.com/publication/fusion_vldbTutorial.pdf)
- Instance ambiguity (a source interpreting an identifier as a different entity) was measured as its own cause of inconsistency, separate from error. **[full text]** — [Li et al., Deep Web, §3](https://arxiv.org/abs/1503.00303)

### Inferences
- **A two-level model is enough and matches practice.** Wikidata, MusicBrainz and Open Library each settled on two layers (work / edition; release group / release) rather than FRBR's four. For manga this suggests: *Work* (the series as an intellectual creation: canonical title, authors, original-run status, total chapter count as serialised) and *Edition* (tankōbon, bunkoban, kanzenban, omnibus/3-in-1, digital, per-language licensed release: volume count, per-volume chapter ranges, publisher, ISBNs, edition-run status). Chapter count is plausibly work-level; volume count and chapter-to-volume mapping are edition-level. This mapping is my own; no source discusses manga.
- **F1 becomes detectable instead of out-votable.** If each provider record is linked to an edition (or to "edition unknown"), then a provider reporting 12 volumes against a consensus of 34 with a consistent internal manifest is evidence of *a second edition*, exactly as ten Weezer releases with different track lists are one release group. Internal consistency plus disagreement with consensus is the signature of a different edition, not of a noisy source. The rule "large coherent disagreement ⇒ suspect different edition, not low reliability" is my inference from the Deep Web ambiguity finding.
- **Related-but-different works.** Open Library's list (adaptation, novelization, partial work, parody ⇒ separate work) corresponds to the manga cases that cause wrong bindings: spin-offs, light-novel originals, anthology comics, coloured editions, sequels with a suffix. A link type of *related-to(kind)* between works lets the matcher record "this candidate is the light novel of the same franchise" as a durable negative rather than re-discovering it each run.
- **Fellegi–Sunter at small scale.** With 6–8 providers and thousands of titles, m and u can be estimated by counting over the existing manually confirmed bindings (m: how often does start year agree among known-correct links; u: how often does it agree among random non-links). No EM or library is required; the result is a transparent additive score with fields such as normalised title similarity band, start year, author overlap, format/media type, volume-count band, and shared external IDs. External cross-reference IDs carried by one provider for another are near-deterministic evidence (very high m, near-zero u). This recipe is an inference from the model, not a published manga-specific procedure.
- **Independence caveat.** Title, romanised title and synonyms are strongly correlated; treating them as separate fields would double-count. Collapse them into one best-title comparison.
- **Three-way decision.** The classical model's two thresholds give match / possible match / non-match. "Possible match" should result in *no bind and no contribution to fusion* rather than a low-weight vote; a wrongly linked record is the F1 failure.
- **Collective ER** is relevant in one narrow way: a provider's parent/child or prequel/sequel/adaptation relations can disambiguate candidates (if candidate A is listed as "adaptation of" candidate B, they are not the same edition). Full collective clustering is unnecessary at this scale.
- **Blocking** (restricting comparisons to candidate pairs sharing a key) is not a real concern here: each provider's own search already returns a handful of candidates per title, which is the block.

### Gaps
- The IFLA LRM text itself (definitions of work/expression/manifestation/item, representative-expression attributes, aggregates) was not retrieved; only an encyclopedia summary and a search snippet of an RDA slide deck were. The claim about serial issues as aggregate manifestations is unverified against the primary text.
- The Fellegi & Sunter 1969 paper was not retrieved; the model is cited from Splink's documentation.
- No documentation was found on how MusicBrainz Picard scores candidate releases (the options-matching documentation URL returned 404), so no default similarity thresholds are reported.
- No source was found describing how Wikidata, MusicBrainz or any library standard models manga specifically (tankōbon vs kanzenban vs omnibus, or chapter-to-volume mapping across editions).
- No small-scale empirical study of Fellegi–Sunter with only a few hundred labelled pairs was found; adequacy of count-based m/u estimation at that size is assumed.

## 3. Constraint-based repair: integrity constraints to detect and repair conflicts

### Takeaway
Denial constraints are the standard language for "these values cannot all be true together", and the research systems built on them (holistic repair, HoloClean) combine constraint violations with other signals to choose repairs. For a per-volume chapter manifest the constraints are few and fully known, so they are best used as detectors that mark a source's manifest as inconsistent or mark the fused record as unknown, rather than as an engine that edits values until the constraints pass.

### Cited Findings
- Holistic Data Cleaning lets users state quality rules as denial constraints with ad-hoc predicates including numerical comparisons; the language subsumes earlier formalisms; interacting violations of heterogeneous constraints are encoded in a conflict hypergraph that defines the repair context. **[abstract]** — [Chu, Ilyas & Papotti, "Holistic Data Cleaning: Putting Violations Into Context", ICDE 2013](https://cs.uwaterloo.ca/~ilyas/papers/XuICDE2013.pdf)
- Denial constraints are described as a more expressive integrity-constraint language than earlier ones, and can be discovered from data. **[abstract]** — [Chu, Ilyas & Papotti, "Discovering Denial Constraints", PVLDB 2013](https://cs.uwaterloo.ca/~ilyas/papers/ChuVLDB2014.pdf)
- HoloClean unifies qualitative repair signals (integrity constraints, external data) with quantitative ones (statistical properties of the data) in one probabilistic inference problem, reporting average precision of about 90% and average recall above about 76% across datasets, and scaling to millions of tuples. **[abstract]** — [Rekatsinas, Chu, Ilyas & Ré, "HoloClean: Holistic Data Repairs with Probabilistic Inference", 2017](https://arxiv.org/abs/1702.00820)
- Within truth discovery, prior knowledge about related facts can be encoded as propositional constraints applied each iteration; because constraints can contradict each other, an "unknown" answer is added per object to keep the problem feasible. **[full text]** — [Li et al. survey, §3.3.2, §3.5.2](https://arxiv.org/abs/1505.02463)
- Local Closed World Assumption: candidate values that violate trusted external knowledge are rejected for that object. **[full text]** — [Li et al. survey, §3.4.1](https://arxiv.org/abs/1505.02463)
- Optimization-based truth discovery can take prior knowledge "as extra equality or inequality constraints". **[full text]** — [Li et al. survey, §2.2.4](https://arxiv.org/abs/1505.02463)
- Related attributes of one object (birth year and age) are an example of object relations most methods ignore but which "could improve the results". **[full text]** — [Li et al. survey, §3.3.2](https://arxiv.org/abs/1505.02463)

### Inferences
All of the following is this researcher's application of the constraint idea; no retrieved source addresses interval partitions.
- **The manifest constraints as denial constraints.** For one edition, with volumes v ordered by number and each having a chapter range [start_v, end_v]:
  1. Well-formed: not (start_v > end_v).
  2. Monotone: not (v < w and start_v ≥ start_w).
  3. Non-overlapping: not (v < w and end_v ≥ start_w).
  4. Contiguous: not (w = v+1 and start_w ≠ end_v + 1) — a *soft* constraint, since bonus/decimal chapters and unreleased middle volumes exist.
  5. Coverage: max(end_v) ≤ chapterCount, with equality only when the edition is complete and all volumes are known.
  6. Cardinality: number of ranges ≤ volumeCount.
  Checking these is a sort plus one linear pass.
- **Check per source before fusing.** A provider manifest that passes 1–3 is internally coherent; one that fails is discarded *as a manifest* (its scalar claims can still vote). A manifest should be fused or adopted as a unit from one source/edition: mixing ranges from two providers almost guarantees overlap or gaps if they describe different editions (F1 again).
- **Cross-field constraints localise the bad scalar (F2).** Constraint 5 and 6 tie the manifest to the scalars. When a violation involves one scalar and many mutually consistent ranges, the minimal explanation is that the scalar is wrong, not the ranges — this is the "repair context" idea from holistic cleaning applied by hand. The practical rule: a derived limit (e.g. "no chapter above N") should be computed from a value only after that value has survived cross-checks against independent evidence (file-backed chapters, a second provider, the manifest's own maximum), and should otherwise not be derived at all. A single unconfirmed scalar should never be the sole input to a destructive limit.
- **Prefer detect-and-abstain to auto-repair.** HoloClean's own reported precision of about 90% means roughly one automatic repair in ten is wrong on its benchmark data, with far more statistical signal than a manga pipeline has. At thousands of entities a wrong auto-repair is F3 (an invented value). The safer use of constraints is as a gate: on violation, keep last-known-good or write unknown, and record which constraint failed.
- **If repairs are made, label them.** Minimal-change repairs (e.g. closing a one-chapter gap by extending a range) are mediating values in the tutorial's sense and should carry provenance "derived: constraint repair", distinct from sourced values.
- **HoloClean-style learned repair needs more data than this setting has.** It learns from the statistical regularities of large tables; a table of a few thousand series with a handful of numeric fields offers little co-occurrence signal. This is an inference from the abstract's framing, not a stated limitation.

### Gaps
- Only abstracts of the denial-constraint and HoloClean papers were retrieved; the precise repair objective (e.g. cardinality-minimal repair) and HoloClean's minimum data requirements are not verified.
- No literature was found on consistency checking or repair of interval partitions / range manifests from multiple sources.
- No source was found on soft vs hard constraints for bibliographic numbering (decimal chapters, bonus chapters, omnibus renumbering).

## 4. Provenance and stability: recording where each value came from and avoiding flapping

### Takeaway
Wikidata's statement model is the clearest worked example: keep every sourced claim with its reference, mark one as preferred, mark known-wrong ones as deprecated with a reason, and represent "unknown" and "none" as explicit positive statements. Stability comes from separating the store of claims (append-only, per source) from the choice of the displayed value, and changing that choice only under hysteresis or review — the pattern monitoring systems use for flap detection and MusicBrainz uses for edits.

### Cited Findings

**Wikidata: claims, references, ranks, unknown**
- Wikidata records what sources say; references "point to specific sources that back up the data provided in a statement". When sources disagree, "All values may be added" with qualifiers, and consensus "should be indicated by a preferred rank". **[full text]** — [Wikidata Help:Statements](https://www.wikidata.org/wiki/Help:Statements)
- *Unknown value* is "a positive statement that that information has not been preserved"; *no value* is a positive statement of absence (Elizabeth I has no value for child). **[full text]** — [Wikidata Help:Statements](https://www.wikidata.org/wiki/Help:Statements)
- Ranks: *normal* is the default; *preferred* is for "the most current statement or statements that best represent consensus"; *deprecated* is for statements "known to include errors" and should carry a "reason for deprecated rank" (P2241) qualifier. Correct historical values are not deprecated; they get start/end time qualifiers. **[full text]** — [Wikidata Help:Ranking](https://www.wikidata.org/wiki/Help:Ranking)
- Consumers get the "best" rank by default: preferred statements if any exist, otherwise normal ones; deprecated statements "will never be used unless that is specifically requested". The full set with qualifiers and references remains queryable. **[full text]** — [Wikidata Help:Ranking](https://www.wikidata.org/wiki/Help:Ranking)

**MusicBrainz: human-in-the-loop edits**
- Most edits stay open 7 days; three unanimous votes close an edit early; an edit with no votes is applied at the end of the period; auto-editor edits apply immediately. **[full text]** — [MusicBrainz, Introduction to Voting](https://musicbrainz.org/doc/Introduction_to_Voting)
- Removals and merges are classed as *destructive* "because they are hard to reverse" and stay open at least 48 hours even with three yes votes. A first No vote extends the deadline so the editor can respond. **[full text]** — [MusicBrainz, Introduction to Voting](https://musicbrainz.org/doc/Introduction_to_Voting)

**Open Library**
- Re-parenting an edition to a different work and merging are explicit, privileged operations. **[full text]** — [Open Library, Editing FAQ](https://openlibrary.org/help/faq/editing)

**Hysteresis / flap detection**
- Nagios keeps the last 21 check results (20 possible state changes), computes a percent state change weighted toward recent changes, and uses two thresholds: flapping starts at or above the high threshold and stops only below the low threshold; between them the status is unchanged. While flapping, normal notifications are suppressed. **[full text]** — [Nagios Core, Detection and Handling of State Flapping](https://assets.nagios.com/downloads/nagioscore/docs/nagioscore/4/en/flapping.html)

**Out-of-date vs wrong, and source dynamics**
- A value can be true, false, or out-of-date; "taking the most recent value may end up with a wrong value". **[full text]** — [Dong & Naumann tutorial](https://lunadong.com/publication/fusion_vldbTutorial.pdf)
- Dynamic-source quality is measured by coverage, exactness (how many updates conform to reality) and freshness (how quickly a new value is captured), not accuracy alone. **[full text]** — [Li et al. survey, §3.2.3, §3.2.5](https://arxiv.org/abs/1505.02463)
- Source accuracy was "fairly steady" over a month in the Deep Web study (average standard deviation 0.06 Stock, 0.05 Flight), yet many sources had "low and unstable quality". **[full text]** — [Li et al., Deep Web, §3.3](https://arxiv.org/abs/1503.00303)
- Most truth-discovery methods are batch algorithms that must be re-run when data changes; some methods had run-to-run instability from randomisation or normalisation and needed multiple executions to average. **[full text]** — [Li et al. survey, §3.1.6](https://arxiv.org/abs/1505.02463); [Waguih & Berti-Equille, conclusions](https://arxiv.org/abs/1409.6428)
- Truth-discovery outputs are opaque ("the reliability degree of a source is 6"); explanation work lists positive and negative evidence for each decision over its alternatives. **[full text]** — [Li et al. survey, §3.5.5](https://arxiv.org/abs/1505.02463)
- "Pass it on" (escalating the conflict to the user or application) is a recognised strategy, as is "Take the information" (prefer a value over null). **[full text]** — [Dong & Naumann tutorial](https://lunadong.com/publication/fusion_vldbTutorial.pdf)

### Inferences
All of the following is this researcher's design reasoning from the patterns above.
- **Claims table, not delete-and-rebuild.** The Wikidata shape maps directly: one row per (entity, edition, field, source) holding the claimed value, fetch time, source record ID/URL, and a state (current / superseded / rejected-with-reason). The stored "truth" is a pointer to a winning claim (preferred rank) or an explicit unknown. A provider failure then leaves its last claim in place with an older timestamp instead of removing its vote, which removes the largest mechanical cause of F4: a fetch error changing the electorate.
- **F3 by construction.** If the stored value must reference a claim row, an invented value has nowhere to live. Derived values (constraint repairs, sums of ranges, ordinal fallbacks) get their own provenance kind ("derived from claims X, Y by rule R") and are never presented as a provider's statement. "Unknown" and "none" should be first-class stored values, as in Wikidata, not nulls that downstream code fills in.
- **Deprecate, don't delete.** Wikidata's deprecated-with-reason is the same idea as a durable rejection record: "provider P's record R is a different edition" should persist so the next run does not re-adopt it. Reason codes worth having: different-edition, different-work, out-of-date, constraint-violation, manual.
- **Hysteresis for the winner.** Apply the two-threshold idea to fusion: a challenger value replaces the incumbent only if it beats it by a margin (not merely a tie-break) and has been observed on N consecutive fetches or for a minimum dwell time; otherwise the incumbent stays. An entity whose winner would have changed more than k times in the last m runs is flagged as flapping and frozen at last-known-good pending review, mirroring Nagios's suppression. Thresholds are design parameters, not literature values.
- **Monotone fields.** For a completed series nothing should change; for an ongoing series chapter and volume counts should only rise. A decrease is far more likely a provider regression or re-binding than a real-world change, so decreases should require stronger evidence than increases. This asymmetry is my inference from the out-of-date discussion.
- **Sticky tiers.** Precedence in the style of MusicBrainz auto-edit vs voted edit: manual override > confirmed (survived hysteresis and constraints) > provisional (single-run winner) > unknown. Destructive downstream actions (pruning chapters above a limit, deleting rows) should depend only on confirmed or manual values, by analogy with the longer hold on destructive edits.
- **Last-known-good with staleness.** Each claim carries fetched-at; a stale claim keeps voting at reduced weight or as a lower bound until a freshness limit, then drops to "no current claim" — distinct from a claim of null.
- **Deterministic fusion.** With fixed weights and deterministic tie-breaks (e.g. incumbent wins ties), identical inputs give identical outputs; iterative methods with random initialisation do not guarantee this, per the evaluation paper.
- **Explainability.** Storing, per decision, the supporting and opposing claims gives the "snapshot explanation" the survey describes at no extra cost.

### Gaps
- No source was retrieved for HTTP-style stale-while-revalidate / stale-if-error semantics or for circuit-breaker patterns; the last-known-good recommendation rests on general engineering practice and is uncited.
- No published account was found of how MusicBrainz, Open Library or Wikidata handle *automated* re-imports that would overwrite a human decision (bot-vs-human precedence), beyond the rank and voting documents.
- Nagios's default flap thresholds are not stated on the page retrieved.
- No literature source was found that evaluates hysteresis or dwell-time rules specifically for data fusion outputs; the survey only notes that streaming/dynamic truth discovery exists.
- Wikidata's help page does not state what an unreferenced statement should be taken to mean.

## 5. Evaluation: a small gold set, per-field accuracy and per-source reliability

### Takeaway
The benchmarks build gold standards from a random sample of roughly 100–200 objects whose values are taken from, or voted among, a few authoritative sources, and they report that these gold standards themselves contain errors and coarse values. Measuring each source's accuracy per field against such a sample, and feeding that in as the weights, is what the Deep Web study found improved every method — and it replaces hand-set confidences with measured ones without any training infrastructure.

### Cited Findings
- Gold standard construction (Stock): 100 NASDAQ symbols plus 100 randomly selected symbols; values voted among 5 popular financial sites, only for items provided by at least three of them; values normalised. (Flight): data from the three airline websites on 100 randomly selected flights. **[full text]** — [Li et al., Deep Web, §2](https://arxiv.org/abs/1503.00303)
- "Generating gold standards is challenging when we cannot observe the real world in person but have to trust some particular sources"; trusting particular sources "sometimes puts wrong values or coarse-grained values in the gold standard"; the authors ask whether uncertainty for some gold items can be captured. **[full text]** — [Li et al., Deep Web, §2, §5](https://arxiv.org/abs/1503.00303)
- Metrics used: *source accuracy* = fraction of a source's values that match the gold standard among its items in the gold standard; *coverage* = fraction of items a source provides; *precision of dominant values*; fusion *precision* and *recall* against the gold standard; *trustworthiness deviation* = RMS difference between sampled and method-computed trustworthiness. **[full text]** — [Li et al., Deep Web, §3–4](https://arxiv.org/abs/1503.00303)
- Accuracy and coverage are independent axes: airport sources averaged .94 accuracy with .03 coverage; in Flight, source accuracy ranged from .43 to .99 with an average of .80. **[full text]** — [Li et al., Deep Web, §3.3](https://arxiv.org/abs/1503.00303)
- Error analysis: the authors hand-categorised a random sample of 20 errors of the best method per domain to attribute causes. **[full text]** — [Li et al., Deep Web, §4](https://arxiv.org/abs/1503.00303)
- Suggested seed for trustworthiness: "the seed can come from sampling or based on results on the data items where data are fairly consistent". **[full text]** — [Li et al., Deep Web, §5](https://arxiv.org/abs/1503.00303)
- Standard metrics: accuracy / error rate for categorical data, MAE and RMSE for continuous data, when ground truth is available. **[full text]** — [Li et al. survey, §3.5.4](https://arxiv.org/abs/1505.02463)
- Objects on which all sources agree may be removed before truth discovery, and one study reported this improved effectiveness; the survey cautions these records still affect reliability estimation, so the step "should be carefully examined". **[full text]** — [Li et al. survey, §3.1.2](https://arxiv.org/abs/1505.02463)
- Sources with very few claims cannot have reliability estimated accurately as a point value; CATD reports a confidence interval instead. **[full text]** — [Li et al. survey, §3.2.5](https://arxiv.org/abs/1505.02463)
- Gold standards in prior comparisons were typically "less than 10% of the original data set's size"; Waguih & Berti-Equille argue such samples are not statistically significant for comparing methods and use a synthetic generator with complete ground truth, though they found their synthetic results corroborated a carefully chosen 100-book gold standard. **[full text]** — [Waguih & Berti-Equille, §1, §4](https://arxiv.org/abs/1409.6428)
- Parameter settings tuned for one dataset did not maximise precision on others. **[full text]** — [Waguih & Berti-Equille, parameter-setting conclusions](https://arxiv.org/abs/1409.6428)
- Hidden golden tasks: quality generally rises with a higher proportion of golden tasks, with improvements varying by method and dataset. **[full text]** — [Zheng et al., PVLDB 2017, §6.3](https://www.vldb.org/pvldb/vol10/p541-zheng.pdf)
- With ground truth available, source accuracies can be learned by empirical risk minimisation rather than EM, and few labels can suffice. **[abstract]** — [Joglekar et al., SLiMFast](https://arxiv.org/abs/1512.06474)
- Fellegi–Sunter m and u are per-field probabilities that can be estimated from data (u from random pairs). **[full text]** — [Splink documentation](https://moj-analytical-services.github.io/splink/topic_guides/theory/fellegi_sunter.html)

### Inferences
All of the following is this researcher's procedure, assembled from the practices above.
- **Gold set shape.** About 150–300 series, stratified rather than purely random so the hard cases are represented: completed vs ongoing, long vs short, titles with multiple editions (kanzenban/omnibus), titles with spin-offs or light-novel originals, obscure titles with thin coverage. A purely random sample would be dominated by easy unanimous cases, which the survey notes contribute little to distinguishing sources.
- **Gold values keyed by edition.** Each gold row should state *which edition* it describes (e.g. original Japanese tankōbon), with the publisher's own listing as the preferred authority and voting among authoritative sources only as fallback, following the Deep Web construction. Record a confidence or "uncertain" flag per gold cell, since that paper found errors in its own gold standard.
- **Per-(source, field) scorecard.** For each provider and field: coverage, exact-match accuracy, and for numeric fields signed error (to separate "stale-low" from "wrong"), plus a categorised reason for each miss: different-edition, out-of-date, parse error, wrong work, genuinely wrong. The reason split matters more than the headline number, because different-edition misses are a linkage defect and should not lower the fusion weight.
- **Weights from accuracy with uncertainty.** With n gold items per (source, field) often below 100, use an interval-aware estimate (e.g. a smoothed accuracy (correct + 1) / (n + 2), or the lower bound of a binomial interval) so a provider with 9/9 does not outrank one with 180/190 — the CATD idea done with arithmetic. Convert to vote weights with the log-odds of accuracy, the form used in Bayesian/Accu-style voting. The specific smoothing is my choice and is uncited.
- **Status confusion matrices.** For publication status, tabulate provider-reported vs gold status per provider (Dawid–Skene's worker model, counted rather than fitted).
- **Linkage is scored separately.** Evaluate binding (is the provider record the right work and edition?) as its own precision/recall on the gold set before scoring field accuracy; otherwise linkage errors are misread as unreliable sources.
- **Bootstrap, then verify.** Following the Deep Web suggestion, items where all linked providers agree can seed initial weights cheaply; the hand-checked gold set then corrects them. Agreement-only seeding is biased toward copy groups, so it should not be the final word.
- **Regression harness.** Replaying stored provider responses for the gold set through the fusion code gives a deterministic before/after accuracy number per field for any change, and a stability metric: the fraction of gold fields whose fused value differs between two replays of consecutive snapshots.
- **Hold-out.** Because tuned parameters did not transfer across datasets in the evaluation paper, thresholds (hysteresis margins, bind cut-offs) should be tuned on one half of the gold set and reported on the other.

### Gaps
- No source gives a sample-size rule for estimating per-source accuracy with a stated margin of error in a fusion setting; the 150–300 figure is a judgement, not a cited number.
- The SLiMFast claim about the number of labels needed is from the abstract only and may depend on features unavailable here.
- No published evaluation methodology specific to bibliographic or comics/manga metadata aggregation was found.
- Binomial-interval or Bayesian smoothing for small-sample source accuracy is standard statistics but no citation was retrieved for it this session.
- How to weight a source whose gold-set coverage is zero for a field (a new provider) is not addressed by the retrieved literature beyond the semi-supervised and prior-initialisation remarks in the survey.
